# 资源预下载（首页离线缓存）

(i18n-ignore-file: 本文档只给维护者看，不参与界面本地化。)

游戏第一次打开时，932 MiB 的素材（干员立绘、spine 模型、音频、界面图）是按需下载的：翻到哪个干员才下哪个，所以第一次进某些界面会卡一下，网络差的时候更明显。这个模块在**首页**放一个浮标，玩家可以先把全部素材悄悄下到本机，之后再进游戏就不需要再走网络。

它**不挡进入**：浮标是纯覆盖层，下载在后台跑，随时可暂停；游戏本身不 import 这里的任何代码，也不等它。

---

## 1. 它做什么

| | |
|---|---|
| 入口 | 首页左下角浮标「资源预下载」，点开是面板 |
| 体量 | 14,177 个文件 / 932.5 MiB（随素材更新变化，见 §3） |
| 首次 | 必须手点一次「开始预下载」——932 MiB 不能偷偷开始 |
| 之后 | 记住「已经开始过」，下次打开首页静默续传（面板里有开关） |
| 校验 | 每个文件按 `大小-修改时间` 逐个比对，**只有变过的文件会重下** |
| 中断 | 关页面、断网、暂停都不丢进度；下次从缺的那几个继续 |

## 2. 两种模式

Service Worker 和 Cache Storage 都只在**安全上下文**里可用（https，或 http 下的 localhost / 127.0.0.1）。局域网玩家访问的是 `http://<内网IP>:3000`，拿不到这两个 API，所以模块会自动降级，面板右上角的徽章会写清楚当前是哪种：

| 徽章 | 条件 | 存到哪 | 能力 |
|---|---|---|---|
| 离线缓存模式 | https 或 localhost | Cache Storage + Service Worker | 游戏请求直接由 Service Worker 从缓存应答，可离线；能逐个校验文件新旧 |
| 浏览器缓存模式 | 普通 http | 浏览器自带的 HTTP 缓存 | 只能「提前请求一遍」把文件推进浏览器缓存；HTTP 缓存**查不了**，所以无法校验，进度按请求数统计，重跑会重新请求全部（命中缓存的走磁盘，不费流量） |

两种模式都不需要玩家做任何选择。想要完整能力就把服务器放到 https 后面（`docs/DEPLOY.md` 里的 cloudflared / 反向代理），或者让玩家用 `localhost` 访问。

> **普通 http 下的实测限制（重要）**：HTTP 缓存的容量由浏览器自己决定，页面既查不到也控制不了。实测单个素材的缓存完全正常（同一个文件请求 3 次，`transferSize` 587 → 0 → 0，`Cache-Control: public, max-age=86400` 生效），但**装不下全部 932 MiB**：连下两轮 932 MiB 后，第二轮仍然产生几乎等量的网络传输，浏览器缓存目录只剩几 MB。也就是说，普通 http 下预下载是**尽力而为**——能留下多少取决于浏览器的缓存预算和 LRU 淘汰，不保证玩家进游戏时还在。要「确定下好了、可离线」，只有 https / localhost 这一条路。

## 3. 服务端：`/preload/manifest.json`

`server/http/preload.js` 生成的工作清单，**虚拟文件**（和 `/data.js` 一样，不落盘），挂在 `server/http/static.js` 里：

```jsonc
{
  "v": 1,
  "version": "7ae1d03466cb-14177-977761181",  // <素材hash>-<文件数>-<字节数>
  "hash": "7ae1d03466cb",
  "files": 14177,
  "bytes": 977761181,
  "groups": [
    { "id": "spine", "label": "立绘 / 模型 (spine)", "files": 3353, "bytes": 475333889,
      "items": [ ["/assets/spine/…/x.atlas", 814, "32e-1a11fa4adc8"], … ] }
  ],
  "missing": []                                 // 清单里有、磁盘上没有的文件（正常应为空）
}
```

- 素材来源：`data/assets.json`、`data/local-assets.json`、`data/emotes.json` 里所有 `/assets/`、`/fonts/`、`/audio/`、`/media/` 开头的字符串，去重后按 URL 排序。
- `items` 的第三个元素是 `server/http/files.js` 导出的 `fileTag(stat)`（`<大小 hex>-<mtime毫秒 hex>`），也就是 `serveFile` 写进 ETag 的那个强校验值的**裸值**（ETag 外面还有引号，gzip 时尾巴多一个 `-gz`）。浏览器端 `normalizeTag()` 把 ETag 还原成同样格式再比。
  - **这个格式只能有一份实现**。两边各写一份，哪天格式漂了，预下载会每次都把全部文件重下一遍，而且不报错。
- 响应：`ETag: "pl-<version>"`、`Cache-Control: no-cache`、`Vary: Accept-Encoding`；`Accept-Encoding: gzip` 时压缩（1.17 MB → 186 KB，6.3 倍）。清单 60 秒内复用，素材清单的 `名称:大小:mtime` 一变就重建。服务器启动时 `warm()` 先算一遍，第一次打开首页不用等。

## 4. 浏览器端：写入与校验

`public/js/preload/engine.js`（状态机）+ `panel.js`（界面）。一次完整流程：

1. 取清单 → 打开缓存 `sp-assets-<hash>` → 把旧的 `sp-assets-*` 删掉（hash 变了才是新缓存名）。
2. **校验**：并发 32 逐个 `cache.match(url)`，比对存的 ETag 和清单里的 tag；缺失或不一致的进待下载列表。纯本地操作，不发请求。
3. **下载**：并发 6（http 模式 8），每个 `fetch(url, {cache:'no-store', headers:{'x-sp-preload':'1'}})`，`cache.put()` 存起来。
4. 告诉 Service Worker「缓存名是 X，版本是 Y」，此后游戏的素材请求由它从缓存应答。

几个刻意的选择：

- **按文件判新旧，不按版本判。** 素材 URL 里没有内容哈希（`tools/fetch-assets.mjs` 是原地覆盖），所以「清单变了」绝不能等于「932 MiB 全丢」。改一张立绘，重跑只搬那几个文件。
- **页面写，Worker 读。** 预下载的请求带 `x-sp-preload: 1`，`resource-sw.js` 见到就放行、不插手，所以每个缓存条目只有一个写入者，不会一份文件下两遍。
- **Worker 不确认版本就绝不读缓存。** 它每次启动都是「只看网络」状态（`cacheName = null`），必须收到页面的 `{t:'sp-assets', cache, version}` 才开始从缓存应答。这条是防止**旧素材被端上来**：万一页面没跑起来（脚本被拦、版本对不上），Worker 不会拿着上一次的缓存硬撑。
- **校验即续传。** 没有断点游标：每次开始都重新校验一遍（本地操作，14k 个条目 1–3 秒），待下载列表自然就是「现在缺的」。失败、被浏览器回收、下到一半关页面，都不用单独记账。
- 首次点开始前会请求 `navigator.storage.persist()`，降低浏览器在磁盘紧张时回收这 900 MB 的概率。

## 5. 界面

- 浮标：左下角胶囊，显示百分比（完成显示 ✓），下载中圆点呼吸。
- 面板：模式徽章、版本、总进度条、已下载/总量、速度、剩余时间、当前文件、**分类明细**（14 组各自进度，展开可看）、错误提示、本浏览器存储占用。
- 按钮：开始/暂停/继续/重新校验/清除，加一个「自动续传」开关。
- 面板展开时才去读清单，所以点开就能看到「要下多少」，不会因为看一眼就开始下载。
- 进入对局后浮标自动隐藏（轮询 `globalThis.__SP__.store` + `js/store.js` 的 `selectRoute`），不会挡战场。用动态 `import()` 拿 `selectRoute`，游戏模块起不来也不影响这个浮标。

## 6. 验证记录（2026-10-10）

- `server/http/preload.js` 直接对真实 `data/` + `public/` 跑：14,177 项 / 932.5 MiB / 14 组 / `missing: 0`，tag 全部合法、URL 无重复，构建 228 ms；GET 200（gzip 186,463 B → 解压 1,169,456 B）、带 `If-None-Match` 得 304、HEAD 正常。
- 无头 Edge 154 打开 `http://127.0.0.1:3000/`：面板渲染、点击展开、徽章「离线缓存模式」、14 组明细；Service Worker 注册为 `activated` 并接管本页；页面写入探针响应后，**不带**绕过头的 `fetch` 拿到探针内容（证明确实由 Worker 从缓存应答），**带**绕过头拿到真实文件（68,256 B），发 `sp-assets-reset` 后不再命中（证明失效保护有效）；控制台无报错。
- 真实续传：预置 `auto: true` 后刷新，无需点击即进入 `downloading`，写入 `sp-assets-7ae1d03466cb`；抽查 400 个缓存条目，**ETag 与清单 tag 全部一致**；暂停后状态停在 `paused`；同时游戏自身 `globalThis.__SP__` 正常就绪。

## 7. 关闭与回滚

- **只对某个玩家关**：面板里「清除」删掉缓存并关掉自动续传，游戏回到原来的按需加载。
- **整体下线**：删掉 `public/index.html` 里那两行（`/css/preload.css` 与 `/js/preload/panel.js`）即可，服务端多出来的 `/preload/manifest.json` 没有页面会去请求；彻底一点再删 `server/http/static.js` 里的 `preload` 三处引用。
- **回到改动前**：`_backup-before-preload-<时间戳>/` 里是 `index.html`、`static.js`、`files.js` 三个文件的改动前原文，直接覆盖回去。新增的文件（`server/http/preload.js`、`public/resource-sw.js`、`public/js/preload/`、`public/css/preload.css`）删掉即可。

## 8. 已知限制

- 普通 http 下没有 Cache Storage，所以**离线玩不了**；而且浏览器 HTTP 缓存装不下 932 MiB，只能起到「提前预热一部分」的作用，能留下多少不保证（见 §2 的实测说明）。这是这个模式下最大的短板，想要确定的结果就上 https / localhost。
- 音频带 `Range` 请求（拖动进度条），Service Worker 一律放行回源，不从缓存应答，否则 206 没法拼。预下载仍然把音频存进缓存，只是播放时不一定走它。
- 932 MiB 存在浏览器里；清站点数据、换浏览器、无痕模式都要重下。iOS Safari 对单个源有配额，可能提前回收。
- 素材更新后，玩家下次打开首页会静默补下改动的那几个文件；版本没变则不重新校验（面板会显示「上次完成，未重新核对」），想确认可以点「校验」。
